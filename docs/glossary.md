# Glossary

The words below have one meaning each, in code, docs and conversation. "File" is not used on its own: it could mean a Source, a Document or a Render.

| Term              | Means                                                                                                                                                                                                                                       | Lives in                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **User**          | A signed-in person. Owns Documents and Sources.                                                                                                                                                                                             | SQLite, managed by Better Auth                                          |
| **Source**        | An image the User uploaded to the server, identified by its content hash. Never modified.                                                                                                                                                   | `.data/sources/<content hash>` on the server's disk                     |
| **Document**      | The editable thing, like a PSD: a permanent id, its owner, its Pipeline and its History. Every image in it is a layer.                                                                                                                      | SQLite                                                                  |
| **Pipeline**      | The Canvas of a Document and its ordered Steps. Each Step acts on the picture the Steps before it made, starting from the blank Canvas; layers are drawn on top.                                                                            | Inside the Document                                                     |
| **Canvas**        | The width, height and background a Document's Steps are drawn on. Stored in the Pipeline, set when the Document is made and changed only by the person.                                                                                     | Inside the Pipeline                                                     |
| **Step**          | One item in a Pipeline: a layer (an image), a Sharp tool or an AI tool, with its options and an on/off switch. A layer draws another image on top of the picture so far; boolean and join channel Steps name their second image themselves. | Inside the Pipeline                                                     |
| **History**       | The undo and redo record of changes to a Pipeline, stored as reversible patches.                                                                                                                                                            | Inside the Document                                                     |
| **Render**        | A cheap image computed from a Document: a preview, a thumbnail or a Sharp intermediate. A cache: it can be deleted at any time and is rebuilt when missing.                                                                                 | `.data/render-cache/`, named by a content hash                          |
| **Result**        | An image that cost real work or that the User asked for: the output of an AI Step, an Export, or a workflow Run. Kept until the User deletes it; never evicted.                                                                             | `.data/results/`, named by a content hash                               |
| **AI tool**       | A Step that runs a model, on the GPU by default. Upscale is the first; others (such as background removal) are added by registering them.                                                                                                   | The AI tool registry                                                    |
| **Export**        | A Result written at full size, downloaded by the User's browser or written to a path by the CLI.                                                                                                                                            | The User's machine, and kept as a Result                                |
| **Document file** | A Document as one `.lemon` file: its name and Pipeline, the Sources it uses and its AI Step Results, stored as the original bytes under their content hashes. Opening one makes a new Document and runs no AI Step again. Not an Export.    | The User's machine; made by the website and the CLI through one service |
| **Job**           | One piece of slow server work (a preview or thumbnail, an AI Step, an export, one Segment of one Source of a workflow run), queued, run by a worker pool, and recorded in SQLite with its progress.                                         | SQLite                                                                  |
| **Workflow**      | A reusable Pipeline, with a Canvas like a Document's, that runs on many Sources. Its input slots are the image layers that are on and have no image; its Output settings say how results are written.                                       |
| **Run**           | One start of a Workflow over its Sources, made of one Job per Source per Segment. It records which canvas it drew on: the Workflow's own, or one the size of each image. Kept until the User deletes it; its Results go with it.            |
| **Segment**       | A draw Segment (the layers and Sharp Steps drawn in one pass) or a single AI Step: the unit one Job of a Run executes. A Run starts and ends with a draw Segment, and the last also encodes the Output.                                     |
| **Key binding**   | The keys that do an action, written as text such as `mod+shift+z`. Everyone starts with the defaults; a User's changes are kept on the server and hold only what differs. See [key bindings](keybindings.md).                               | `default-bindings.json`; SQLite (`keybindings`)                         |

## Rules

- **Opening an image** uploads it as a Source and creates its Document, whose Pipeline starts with a layer for it. Uploading the same image again finds the existing Source by its hash. The UI says "Open image", never "Open file".
- **The Document id** is permanent and is the only id the app and its routes use (`/documents/<id>`). It is the same in every browser, tab and device, and after a server restart.
- **A Source never changes or moves.** It is stored by its content hash, so there is nothing to relink and no "changed Source" state.
- **Ownership:** a User can read and change only their own Documents and Sources. The CLI has no account of its own: it acts as an existing User.
- **Renders are a cache, not data.** Deleting all of them loses nothing.
- **Results are kept.** A Result is never evicted; it goes only when the User deletes it, or its Document or Run. Clearing unused Results removes only AI Step Results the Pipeline no longer uses; Exports are never cleared that way.
- **Cancelling a Job** ends it as cancelled and keeps any Result it already made; it queues no following Jobs.
